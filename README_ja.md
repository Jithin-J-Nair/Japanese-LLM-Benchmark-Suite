# LLM-JP-Bench — 日本語LLMベンチマークスイート

敬語・ビジネス文書に特化した日本語タスクで大規模言語モデル（LLM）を**再現可能に定量比較**するための評価基盤です。AIエンジニアのモデル選定、製品チームの導入判断、研究用途の比較実験を想定して設計しています。

---

## 主な機能

### 5つの日本語評価タスク
1. **敬語リライト** — 砕けた表現をビジネス敬語（尊敬語・謙譲語・丁寧語）へ書き換え
2. **ビジネスメール補正** — 宛名・挨拶・本文・結び・署名の構造とトーンを補正
3. **日本語要約** — ニュース記事を約100字へ要点要約
4. **ビジネス翻訳** — 日英・英日双方向。グロッサリ用語の整合性を検証
5. **OCRクリーンアップ** — 句読点復元・空白正規化・半角カナ修正

### 計測指標（サンプル単位）
- **品質スコア** — タスク別ルーブリックに基づく重み付き0-100点（サブスコアと根拠メモ付き）
- **レイテンシ** — リクエストあたりの応答時間（ms）
- **トークン数** — 入力/出力を分離して記録
- **コスト推定** — APIモデルはUSD換算、ローカルモデルはVRAM使用量を記録

### 7モデルのレジストリ
LLM-jp-3 13B、Qwen2.5 14B、Llama 3.1 8B、Gemma 2 9B、Swallow 7B、ELYZA Llama-3 8B（ローカル量子化）＋ GPT-4o mini（API）。日本語チューニングモデルと汎用モデルの差分が一目で比較できます。

### 可視化・レポート
- モデル×タスクのスコアマトリクス
- レーダーチャート（タスクプロファイル）
- 品質×レイテンシ散布図、タスク別棒グラフ
- サンプル別の出力横並び比較（サブスコア・監査メモ付き）
- **エクスポート**: CSV / JSON / Markdownレポート（主要な所見を自動生成）

### 再現性
すべての乱数は文字列シードから生成する決定的PRNG（mulberry32）に由来します。同じ設定・同じシードなら、何度実行しても**完全一致の結果**が得られます。

## 技術スタック

- **フロントエンド**: Next.js（App Router）、TypeScript、Tailwind CSS v4、Recharts
- **バックエンド**: Next.js Route Handlers
- **永続化**: PostgreSQL + Drizzle ORM
- **評価**: ルールベースのヒューリスティクス（透明性最優先。隠れたLLMジャッジなし）

## セットアップ

```bash
npm install
# .env に DATABASE_URL を設定
npx drizzle-kit push
npm run dev
```

http://localhost:3000 を開くと、初回アクセス時に全モデル×全タスクのデモ評価が自動シードされます。

## 使い方

1. **新規ベンチマーク** でモデル・タスク・シードを選択し実行
2. **実行履歴** から各レポートを参照（スコア表・チャート・サンプル検査）
3. CSV / JSON / Markdown でエクスポートし、社内Wikiや稟議資料へ転用

### サンドボックス / エンドポイントモード
既定は**サンドボックスモード**（GPU不要・オフライン完結の決定的生成）。`docs/models.md` の手順で実エンドポイント（OpenAI互換API / Ollama）を設定すれば、実モデルの計測に切り替え可能です。

### HuggingFace 自動モデル検出
レジストリ画面の**「モデルを更新」**ボタン（または `POST /api/models/refresh`）を実行すると、日本語LLM関連の検索・タグフィルタで Hub をスキャンし、ダウンロード数・ライク・ライセンス・量子化・パラメータ数を抽出して `models_dynamic` テーブルへ **idempotent にアップサート** します。応答は `added / updated / total` のJSONサマリ。検出モデルは **Capability Estimator** がタグ・説明文・パラメータ数から決定的に推定したスキル行列を持ち、即座にベンチマークのモデル選択・レジストリ絞り込み・モデルインスペクタ（`/models/[id]`）へ反映されます。HF API 障害時は指数バックオフでリトライし、全失敗時は既存データを保持したまま構造化エラーを返します。

## 言語設定（i18n）

ナビゲーション・ボタン・表・チャート・フォーム・レポート所見・Markdownエクスポートを含む **UI全体を日本語/英語で切り替え** 可能です。

- サイドバー/モバイルヘッダーの **言語ドロップダウン**、またはナビゲーションの **「設定 / Settings」** ページから切り替えます。
- **ちらつきゼロ設計**: すべてのローカライズ文字列は単一の `LanguageContext` を購読するクライアントコンポーネント経由で描画されます。切替は React の状態更新のみ — ページリロード・`router.refresh()`・レイアウト再マウント・**スクロールリセットは一切発生しません**。
- 設定は `localStorage` とクッキー（`jp-bench-lang`）の両方に保存。クッキーが SSR の初期描画を決定するため、**ハイドレーションミスマッチは起こりません**。
- 初回アクセス時はブラウザ言語を自動判定（日本語→日本語、その他→English）。いつでも上書き可能です。

**翻訳の追加方法:** 表示文字列はすべて `src/i18n/` に集約されています（`ja.ts` がマスターキー定義、`en.ts` は `Record<I18nKey, string>` で型検査）。新しい文字列は `ja.ts` → `en.ts` の順に同キーで追加し、クライアントでは `useLanguage().t(key)`、サーバーページでは `<T/>` 系コンポーネント（`T` / `TaskName` / `RubricLabel` / `ModelDescription` / `LocalDateTime`）で参照します。新言語の追加は辞書実装＋`index.ts` 登録の2ステップです（[docs/i18n.md](./docs/i18n.md) 参照）。なお、モデル出力や監査メモ（日本語の評価データ）はデータ整合のため日本語のまま保持する設計です。
