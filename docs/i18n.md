# i18n — 言語設定アーキテクチャ

LLM-JP-Bench は UI 全体（ナビゲーション・ボタン・表・チャート・フォーム・レポート所見・エクスポート）を日本語/英語で切り替えられる。本ドキュメントでは設計原則・キー構造・拡張手順を説明する。

## 設計原則

1. **単一の真実源（ランタイム）** — 表示言語のライブな正規情報は `LanguageContext` の state のみ。すべての文字列はコンテキストを購読するクライアントコンポーネント（`useLanguage` か `<T/>` 系）から描画される。
2. **ちらつき・スクロールリセットの完全排除** — 言語切替は純粋な state 更新。**`router.refresh()` / ページ遷移 / レイアウト再マウントを一切行わない**。スクロール位置・フォーカス・開いているメニューは維持される。
3. **ハイドレーションミスマッチゼロ** — レイアウトが読む `jp-bench-lang` クッキーが SSR の初期 HTML を決定し、クライアントの初回レンダーは同一値で実行される（クライアントコンポーネントも初回はサーバーで描画されるため両者は一致）。マウント後の同期はローカル state のみを変更するため画面フラッシュが起きない。
4. **型安全なキー** — キー一覧は `ja.ts` の const オブジェクトから `I18nKey` 型として導出され、`en.ts` 側は `Record<I18nKey, string>` で欠落をコンパイル時に検出する。
5. **評価データは非翻訳** — モデル出力・監査メモ（notes）・データセット内容はデータ整合のため生成時の言語（日本語）のまま保持する。ローカライズ対象は UI クロームと計算時生成文字列（主要な所見・Markdownレポート）。

## 構成

```
src/i18n/
  ja.ts      # 日本語辞書（マスター：ここで I18nKey が定義される）
  en.ts      # 英語辞書（Record<I18nKey, string> — キー欠落はコンパイルエラー）
  index.ts   # Language 型 / translate() / taskName・rubricLabel 等のヘルパー
src/context/LanguageContext.tsx        # プロバイダ＋useLanguage()（refresh 不使用）
src/components/language-selector.tsx   # ドロップダウン切替（dark=ナビ / light=設定）
src/components/localized.tsx           # <T/> 系: T, TaskName, RubricLabel,
                                       #   ModelDescription, LocalDateTime …
src/lib/server/i18n.ts                 # cookie の SSR シード解決（getServerLang）
src/app/settings/page.tsx              # 設定ページ
```

## 言語解決フロー（安定版）

```
[SSR (layout.tsx)]
  cookie jp-bench-lang ─► initialLanguage ─► <html lang> + <LanguageProvider initial>
        │
        ▼ 初回ペイントはサーバー・クライアントで完全一致
[Client]
  useLanguage() / <T/>  ── すべての文字列は context state から描画
        │
        ▼ LanguageSelector onSelect
  setLanguage(lang):
    1. setState(lang)            ← UI 即時更新（刷新なし・スクロール維持）
    2. localStorage ← lang       ← 永続化（次回訪問の初期値）
    3. cookie ← lang             ← 次回フルロード時の SSR シード
    4. document.documentElement.lang ← lang

[マウント時同期（1回のみ・state のみ）]
  localStorage → なければ cookie → なければ navigator.language(ja*→ja / else→en)
  ※ 状態遷移のみで再フェッチは発生しない
```

## `t()` の使い方

```tsx
// クライアント
const { t, language } = useLanguage();
t("nav_models")                                 // モデルレジストリ / Model Registry
t("models_result_count", { n: 5, total: 59 })   // 変数補間 {n}

// サーバー
const t = await serverT();
t("dashboard_title")
```

## ドメインラベルヘルパー

タスク・データセット・ルーブリック・モデルの表示名は辞書キー規約で解決（ドメインレジストリを非侵襲に保持）:

| ヘルパー | キー規約 | 例 |
| --- | --- | --- |
| `taskName/lang` | `task_<id>_name` | `task_keigo_rewrite_name` |
| `taskShort` | `task_<id>_short` | 敬語 / Keigo |
| `taskDesc` | `task_<id>_desc` | 説明文 |
| `datasetName/Desc` | `dataset_<id>_(name|desc)` | |
| `rubricLabel` | `rubric_<metric>` | rubric_politeness |
| `modelDesc` | `model_<id>_desc`（静的モデルのみ。動的はHF説明＋ローカライズ接尾辞） | |

## 新しいUI文字列の追加手順

1. `src/i18n/ja.ts` にキーを1行追加（日本語を先に定義）。
2. `src/i18n/en.ts` に同キーの英訳を追加（漏れは tsc で検出される）。
3. 呼び出し側で `t("my_new_key", { var })` を使用。

## 新しい言語の追加手順

1. `src/i18n/<lang>.ts` を作成し `Record<I18nKey, string>` を実装。
2. `index.ts` の `Language` 型・`LANGUAGES`・`DICTS`・`LANG_COOKIE` 値の解決を拡張。
3. `src/components/language-selector.tsx` の `OPTIONS` 配列に選択肢を追加。
4. ブラウザ検出ロジック（`LanguageContext` mount effect）に言語コードを追加。

## 既知の設計判断（意図的）

- **評価アーティファクトは日本語固定**: `notes`（監査メモ）は生成時永続化され、DBの既存行との混在を避けるため翻訳しない。主要な所見・Markdownエクスポートは描画/生成時の言語で動的生成。
- **FOUC の扱い**: cookie 未設定の初回は 'ja' で SSR し、英語ブラウザはマウント直後に 'en' へ切替（再現可能で単純な優先順位: localStorage > cookie > navigator）。
